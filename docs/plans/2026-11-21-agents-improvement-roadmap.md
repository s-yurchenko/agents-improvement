# План развития agents-improvement

Статус: назначение, порядок работы и стартовый объём согласованы с владельцем 21 ноября 2026 года по итогам интервью. Состав и точный текст инструкций подтверждены. 22 ноября реализован и опубликован первый релиз плагина для Codex с поддержкой Claude Code. Автоматические проверки пройдены; установка из GitHub и дословная передача базовых инструкций в новый чат Codex подтверждены.

## Назначение и аудитория

`agents-improvement` — публичный личный набор инструкций и скиллов для работы с агентами. В первую очередь он нужен владельцу для собственных задач; другие могут пользоваться опубликованными материалами. Развитие идёт небольшими законченными шагами в свободное время, без заранее заданного расписания.

Главная польза — не приходится каждый раз повторять одни и те же требования. Агент помогает доводить проекты от идеи до работающего результата, самостоятельно выполняет доступную ему работу, а владелец понимает существенные решения и может на них влиять.

Инструкции и личные скиллы хранятся в одном месте. Желаемый сценарий: дать агенту ссылку на репозиторий и подключить нужный набор. Первый целевой клиент — Codex Desktop; совместимость с Claude Code заложена в плагине. Новая задача означает новый чат.

## Ценность формулировок

- Дословные формулировки — основная ценность содержимого репозитория.
- Утверждённые правила сохраняются без перефразирования. Состав набора и совпадение текста должны быть доступны для сверки.
- Новые правила после подтверждения включаются в общий список с тем же статусом. Сохраняются их формулировки, включая пунктуацию и пояснения.
- Согласованный порядок работы и обновлений входит в базовые инструкции.
- Редакторские пояснения, отложенные варианты и подключаемые инструкции должны быть явно различимы. Изменение выбранной формулировки требует согласования.

Утверждённый текст общей основы хранится в [prompts/base.md](../../prompts/base.md), отдельный вариант с Graphify — в [prompts/optional/graphify.md](../../prompts/optional/graphify.md). Состав набора и результат проверки сохранены в [записи сверки](../prompts/system-prompts-review.md). Правила состава описаны в [каталоге инструкций](../../prompts/README.md). Подключение и текущие ограничения описаны в [документации плагина](../../plugins/agent-instructions/README.md).

## Согласованный порядок работы

Ниже дословно сохранён порядок из подтверждённого итога интервью:

1. Агент изучает доступный контекст и задаёт вопросы о существенных неизвестных.
2. Предлагает рекомендуемое решение с объяснением выбора. Альтернативы показывает при существенных компромиссах; неудачные предложения с твоей стороны аргументированно оспаривает.
3. Показывает короткое summary: цель, подход, объём ближайшей работы, критерии готовности и способ проверки. Ждёт твоего ответа.
4. Ты можешь внести поправки. После существенных поправок агент показывает обновлённое summary и снова ждёт «начинай».
5. Затем самостоятельно реализует задачу и проверяет результат по согласованным критериям. В конце понятно сообщает результат, оставшиеся вопросы и необходимые действия с твоей стороны.

Обновления правил подхватываются перед следующей задачей. Начатая работа сохраняет согласованные условия.

Для подключения выбран синхронный `SessionStart`: новый чат получает опубликованные Markdown-файлы, продолжение сохраняет полный снимок. Код плагина обновляется отдельно. Архитектура и проверки зафиксированы в [плане плагина](2026-11-22-instruction-plugin.md).

## Основные направления

1. Базовые инструкции с точными формулировками ожидаемого поведения агента.
2. Библиотека личных скиллов для повторяющихся задач. Для уточнения существенных неизвестных используется готовый `grilling`, установленный отдельно; первый переносимый личный скилл ещё выбирается.
3. Удобное подключение и получение обновлений из единого репозитория в Codex и Claude.

Первые два практических результата — сверенный набор базовых инструкций и воспроизводимое подключение к обоим агентам. Технические детали прорабатываются по одному небольшому шагу.

## Границы

- Проверки конкретного проекта остаются частью работы агента; критерии готовности и способ проверки согласуются до реализации.
- Общие наборы линтеров и CI из прежнего плана развития отложены до появления отдельной потребности.
- Стек, архитектура и инструменты выбираются под конкретный проект. Go, TypeScript, Graphify и другие прежние варианты не становятся обязательными для всех проектов.
- Правила с обязательным Graphify сохраняются как отдельный вариант на выбор. Удаление зависимости из текста без согласования недопустимо.
- Примеры ошибок из интервью помогают обсуждать качество поведения, но не превращаются автоматически в специальные правила для таймзон, чатов или конкретных приложений.
- Стек, настройки и внутренние документы отдельных проектов не входят в общую основу.
- Для инструкций реализован один плагин и каталоги Codex/Claude. Генератор конфигураций, автоматизация хостинга и дополнительные плагины не входят в этот шаг.
- Публичность — согласованное намерение. Первоначальный шаг изменения планов не включал публикацию. 22 ноября пользователь отдельно разрешил подготовить и отправить первый релиз в `master`.

## Небольшие законченные шаги

### 1. Обновить планы

Зафиксировать назначение, аудиторию, порядок работы, границы и ближайшие шаги. Прежние планы сохранить как историю, а корневые инструкции направить на актуальный документ.

Готово, когда планы согласованы между собой и не направляют агента начинать с прежнего набора линтеров.

Состояние: документы обновлены по подтверждённому итогу интервью.

### 2. Сверить базовые инструкции

Собрать подтверждённые правила и согласованный порядок работы в единый список. Показать состав набора, проверить сохранность формулировок. Сохранить подтверждённый текст в чистых файлах для будущего подключения.

Готово, когда пользователь проверил полный список и подтвердил состав и формулировки подключаемой основы.

Состояние: выполнено. Пользователь подтвердил полный список. В общей основе двенадцать последовательно пронумерованных разделов: десять правил, порядок работы и обновлений. Оспаривание решений, структура ответа и самостоятельное выполнение работы включены в общий список. Пояснение в скобках в правиле о структуре ответа сохранено дословно. Два правила работы с Graphify подготовлены как отдельный вариант для конкретного проекта.

### 3. Проверить подключение

Выбрать первый агент и его конкретное приложение или режим. Подготовить минимальный способ подключения по ссылке, показать результат и проверить его на практике. Повторить для второго агента. Сохранить воспроизводимую инструкцию подключения и обновления.

Готово, когда подтверждено, какой текст получает каждый агент, как он используется в новой задаче и как обновления применяются перед следующей задачей. Одного факта установки файлов недостаточно: нужно проверить поведение в задаче.

Состояние: версия 0.1.0 установлена из GitHub. В новом чате Codex подтверждена дословная передача всех 12 разделов основы; доверие к хуку подтверждено пользователем. Проверены загрузчик и манифесты Claude. Остаются реальная сессия Claude и применение правил в прикладной задаче. Детали — в [плане подключения](2026-11-22-instruction-plugin.md).

### 4. Проверить пользу на реальной задаче

Пройти одну выбранную задачу в проекте владельца. До реализации согласовать краткий план с критериями готовности; после выполнения сверить результат и отметить требования, которые всё ещё пришлось повторить.

Готово, когда есть проверенный результат задачи и короткая запись о соблюдённых и пропущенных правилах. Такой опыт служит основанием для следующего небольшого изменения набора.

### 5. Добавить один личный скилл

Выбрать повторяющуюся задачу и скилл для неё. Сохранить согласованный текст, описать вызов и ожидаемый результат, проверить подключение и использование в нужном агенте.

Готово, когда скилл находится в едином репозитории и его сценарий пройден на конкретной задаче.

Отдельно согласовано использование готового `grilling` для существенных неизвестных. В выпуск 0.1.1 входит обращение к нему по имени с проверкой доступности и установкой либо подключением только после подтверждения инженера; копия скилла в плагин не добавляется. Это не закрывает этап переноса собственного скилла. Детали — в [плане использования grilling](2026-11-22-grill-me.md).

- Результаты реальной сессии Claude Code.
- Проверка выбора установленного `grilling` в новом чате после публикации обновлённой основы, запроса подтверждения при отсутствии скилла и наличия этого скилла в Claude Code.
- Способ подключения и обновления будущих личных скиллов; обновление Markdown-инструкций уже реализовано отдельно от кода плагина.
- Первая реальная задача для проверки пользы и первый переносимый личный скилл.
