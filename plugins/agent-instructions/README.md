# Инструкции агента

Плагин передаёт агенту полный текст `prompts/base.md` при запуске чата через синхронный `SessionStart`. Выбранные дополнения передаются следом. Формулировки не генерируются и не пересказываются: сохраняются исходный текст, SHA коммита и SHA-256 каждого файла.

Это дополнительные инструкции в контексте клиента. Они не заменяют его системные правила, разрешения и ограничения.

## Требования

- Node.js 20.11+ и Git доступны в PATH процесса Codex или Claude Code.
- Клиент поддерживает плагины и `SessionStart`. Локальная проверка упаковки выполнена с Codex `0.171.0-alpha.13` и Claude Code `2.1.126` на Windows.
- Источник содержит файлы `prompts/` в выбранной ветке. Для источника по умолчанию нужен доступ к HTTPS-репозиторию; интерактивный запрос пароля из хука отключён.

## Codex

Для установки из ветки `master` выполни:

```sh
codex plugin marketplace add https://github.com/s-yurchenko/agents-improvement.git --ref master
codex plugin add agent-instructions@agents-improvement
```

В Codex Desktop открой **Review hooks** в поле ввода или **Settings → Hooks**, проверь `agent-instructions@agents-improvement` и подтверди доверие. Если плагин ещё не появился, перезапусти приложение. После подключения начни новый чат.

Для локальной разработки из корня этого репозитория вместо URL можно использовать `codex plugin marketplace add .`. Это устанавливает код плагина из рабочей папки, но **не меняет источник правил**: по умолчанию загрузчик всё равно читает опубликованный `master` по HTTPS.

Проверить регистрацию и установку:

```sh
codex plugin marketplace list --json
codex plugin list --json
```

Доверие проверяет сам Codex. Изменение кода плагина может потребовать повторной проверки. См. [официальную документацию хуков](https://learn.chatgpt.com/docs/hooks) и [каталогов плагинов](https://developers.openai.com/plugins/build/plugins).

## Claude Code

Для установки выполни:

```sh
claude plugin marketplace add https://github.com/s-yurchenko/agents-improvement.git
claude plugin install agent-instructions@agents-improvement --scope user
```

Пройди штатное подтверждение доверия к источнику и открой новую сессию. Для локальной установки из корня репозитория можно передать `.` вместо URL. Форматы манифестов проверены командой `claude plugin validate`; запуск в реальной сессии остаётся отдельной проверкой.

Плагин использует общий загрузчик и отдельные манифесты и конфигурации хуков для клиентов. См. [манифест Claude](https://code.claude.com/docs/en/plugins-reference) и [SessionStart](https://code.claude.com/docs/en/hooks#sessionstart).

## Что обновляется

| Ситуация | Поведение |
| --- | --- |
| Новый чат, новый идентификатор сессии | Получение актуальных Markdown-файлов из выбранной ветки |
| Продолжение, повторный запуск процесса, сжатие контекста | Тот же полный снимок, без обновления |
| Изменение правил или настроек проекта | Применяется к следующему новому чату |
| Источник недоступен, подходящий кэш есть | Сохранённые правила и явное предупреждение |
| Источник недоступен, подходящего кэша нет | Явная ошибка подключения |
| Продолжение старого чата, созданного до установки | Ошибка с предложением открыть новый чат: прежняя версия неизвестна |

`clear` сохраняет снимок, если клиент оставляет идентификатор сессии прежним. Если клиент создаёт новый идентификатор, загрузчик получает актуальную версию. `fork` с новым идентификатором считается новым чатом.

При ошибке Codex получает `continue: false`, причину и сообщение об ошибке. Claude Code не позволяет остановить `SessionStart`: он получает сообщение в интерфейс и контекст. Сообщение об ошибке означает, что общие правила не подключились.

Обновление Markdown не требует переустановки плагина. Исполняемый код автоматически из источника правил не загружается. Для новой версии самого плагина обнови каталог и плагин средствами клиента; в этой версии командной строки Codex доступны `codex plugin marketplace upgrade agents-improvement` и повторный `codex plugin add agent-instructions@agents-improvement`. В Claude — `claude plugin marketplace update agents-improvement` и `claude plugin update agent-instructions@agents-improvement`.

## Настройки

Без настроек используется `https://github.com/s-yurchenko/agents-improvement.git`, ветка `master`, только базовые инструкции.

Для другого источника создай `config.json` в каталоге данных плагина:

```json
{
  "repository": "https://example.org/owner/agents-improvement.git",
  "branch": "master"
}
```

Также можно задать абсолютный путь к этому файлу через `AGENTS_IMPROVEMENT_CONFIG` в окружении процесса клиента. Удалённый адрес должен быть HTTPS URL без логина, пароля и параметров запроса. Допустим абсолютный локальный путь к Git-репозиторию — загрузчик читает его коммиты, а не незакоммиченные файлы.

Каталог данных выбирается в порядке: `AGENTS_IMPROVEMENT_DATA_DIR`, `PLUGIN_DATA`, `CLAUDE_PLUGIN_DATA`, затем `~/.cache/agents-improvement/<codex|claude>`. Он содержит `config.json`, `last-good/` и `sessions/<клиент>/`. Снимки сохраняются между запусками и не лежат в каталоге установленной версии плагина. Удаление снимков лишает старые чаты возможности восстановить прежние правила; автоматической очистки в первой версии нет.

Для Graphify добавь в корне целевого Git-проекта `.agents/instructions.json`:

```json
{ "optional": ["graphify"] }
```

Без файла или с `{"optional": []}` используется только основа. В папке без Git настройка читается относительно рабочей папки чата. Плагин подключает текст правил; установку Graphify выполняют отдельно в нужном проекте.

## Проверка

Из корня репозитория:

```sh
npm run check
npm test
claude plugin validate plugins/agent-instructions
claude plugin validate .claude-plugin/marketplace.json
```

Тесты проверяют обновление A → B между чатами, сохранение A при продолжении и повторном запуске процесса, параллельные старты, Graphify, отсутствие сети, ошибки данных и точное совпадение подключаемых текстов. Истории Git создаются как изолированные тестовые данные в `.test-artifacts/`, без коммитов в рабочий репозиторий.

Проверка внутри Codex после доверия к хуку:

1. Открой новый чат и попроси назвать версию правил из блока `[agents-improvement]`. Она должна совпадать с SHA опубликованного `master`.
2. Согласуй и опубликуй небольшое изменение правил; в новом чате проверь новый SHA. Сравни полный текст с источником при помощи `codex debug prompt-input` либо сохранённого снимка в каталоге данных.
3. Продолжи первый чат и проверь, что его SHA остался прежним.
4. На небольшой реальной задаче проверь согласование краткого плана и выполнение критериев готовности. Получение текста и соблюдение правил — разные проверки.

На 22 ноября 2026 года автоматические тесты пройдены, оба манифеста Claude валидны, Codex установил плагин и распознал `SessionStart` без ошибок. Доверие к хуку ещё не подтверждено; передача текста через настоящий запуск Codex и реальная сессия Claude пока не подтверждены. Состав и ограничения первого релиза описаны в [заметке о версии 0.1.0](../../docs/releases/0.1.0.md).
