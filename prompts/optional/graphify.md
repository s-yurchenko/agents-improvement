# Дополнительные инструкции: Graphify

## 1. Изучи существующую реализацию до написания кода

Перед изменением изучи затронутые модули, их зависимости, вызывающий код, тесты и документацию. Используй Graphify по правилу 2, затем точечный поиск через `rg` и чтение исходников. Найди подходящие компоненты, функции, типы, контракты и принятые подходы; расширяй существующее решение, когда оно подходит. Создание параллельной реализации требует понятной причины.

## 2. Используй Graphify для работы с зависимостями

[Graphify](https://github.com/Graphify-Labs/graphify) обязателен при анализе архитектуры и изменениях кода: используй граф зависимостей, чтобы находить существующие реализации, связи и места, на которые повлияет изменение.

- Перед анализом проверь доступность инструмента и актуальность графа относительно рабочей копии. При необходимости построй или обнови граф.
- Сначала сузь область через граф, затем проверь найденные связи и выводы по исходникам. Граф помогает навигации; фактический код остаётся основанием решения.
- После изменений обнови затронутую часть графа либо перестрой его доступным инструменту способом, чтобы следующий анализ использовал актуальные данные.
- Команды бери из документации установленной версии. Настройку и воспроизводимый способ обновления графа запиши в `docs`.
- Если Graphify недоступен, сообщи об этом и восстанови/подготовь его подключение. Не выдавай обычный текстовый поиск за выполненный анализ графа. Невозможность подключить инструмент обозначь как открытое препятствие для зависимой работы; независимые задачи можно продолжать.
- Пока исходников нет, явно отмечай, что граф зависимостей кода ещё не построен. Работа только с текстом документации не требует выдумывать отсутствующие связи.
